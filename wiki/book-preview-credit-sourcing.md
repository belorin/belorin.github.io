# 온라인 서점 미리보기와 판권면 수집: 기술적 가능성과 허용 범위

크레딧 데이터베이스를 만들 때 온라인 서점의 '미리보기'는 유혹적인 출처다. 종이책을 매번 열어 사진을 찍지 않고도 판권면을 볼 수 있다면 편집자와 디자이너의 이름을 대규모로 수집할 수 있을 것처럼 보인다. 그러나 **화면에서 볼 수 있음**, **프로그램으로 가져올 수 있음**, **반복적으로 저장·가공·공개할 권리가 있음**은 서로 다른 상태다. 수집 전략은 이 세 가지를 분리해야 지속 가능하다.

## 책 페이지에서 구별해야 할 세 종류의 데이터

| 유형 | 예시 | 적합한 용도 | 별도로 확인할 것 |
| --- | --- | --- | --- |
| 도서 상품 메타데이터 | 제목, 저자·역자, ISBN, 출판사, 출간일 | 대상 도서 목록, 중복 제거, 서지 확인 | API 및 재사용 조건 |
| 책 소개·발췌 텍스트 | 목차, 책 속으로, 서평 | 판권면 존재의 간접 단서 | 저작권·텍스트 복제·표시 조건 |
| 미리보기 뷰어 이미지 | 표지·판권면·본문 페이지 | 이름·직책 OCR의 직접 입력 후보 | 이미지 접근·보관·가공·공개 권한 |

프로젝트에서 필요한 것은 세 번째지만, 실제 시작점은 첫 번째여도 된다. 서점에서 찾은 책을 먼저 **후보 목록**으로 만들고, 판권면은 권한을 확인한 다른 자료원에서 얻을 수 있다. 모든 미리보기 뷰어가 판권면을 제공하는 것은 아니고, 판권면이 보여도 대량 다운로드가 허용된다는 뜻은 아니다.

## 서비스와 자료원별 검토표

이 표는 **현행 약관이나 크롤링 성공 실험을 검증한 결과가 아닌 잠정적인 검토 방향**이다. 특정 업체가 이미 수집을 허용하거나 금지한다고 확정한 것이 아니다.

| 대상 | 메타데이터 접근 방향 | 판권면 접근 방향 | 미확인 사항 |
| --- | --- | --- | --- |
| 알라딘 | 공식 도서정보 API가 제공하는 범위 검토 | 미리보기는 별도 정책 검토 | 실제 필드·요청 제한·이미지 권한 |
| 교보문고 | 상품정보 이용 조건 확인 | 자동 추출·저장 보류 | 뷰어 구조·약관 |
| YES24 | 상품정보와 뷰어 구분 | 자동 추출·저장 보류 | 공식 접근 방식·약관 |
| 리디 등 전자책 서비스 | 허용된 서지정보 확인 | 보호된 전자책 뷰어 내용 추출 지양 | DRM·이용권한·계약 |
| Google Books | 공식 API와 미리보기 링크 확인 | 페이지 이미지 다운로드와 구분 | API 기능·재사용 범위 |
| 출판사 홈페이지 | 자체 서지·샘플 PDF·보도자료 찾기 | 명시적으로 제공된 파일 우선 검토 | 파일별 사용 허용 조건 |
| 도서관·ISBN 서지 | 책 식별과 연대·출판사 보강 | 보통 판권면 OCR 자료의 직접 대체는 아님 | 데이터의 활용 조건 |

특히 서점의 미리보기는 독자의 구매 전 열람을 돕는 기능일 수 있다. 화면에 표시된 출판물 이미지와 제3자의 자동 복제·저장·재게시 권리는 일치하지 않는다. Google Books의 미리보기 링크도 이미지 파일 자체를 받을 권한과는 다르다. 공식 API가 존재하더라도 API가 제공하는 것은 통상 **책의 식별과 설명을 돕는 필드**이지, 편집·디자인·제작팀의 판권면 정보라는 보장은 없다.

## 발견용 목록과 입수한 원본을 분리한다

첫 테이블 `book_candidate`는 작품 후보를 다룬다.

- `isbn`, `title`, `publisher`, `published_on`, `author_text`, `translator_text`
- `source_site`, `source_url`, `has_preview`, `collected_at`

여기서 `has_preview`는 관찰된 표시일 뿐, 이미지 수집이 허용되었다는 플래그가 아니다. 서점·출판사 페이지의 변경으로 값이 달라질 수 있으므로 확인 시점도 남겨야 한다.

두 번째 테이블 `source_asset`은 **실제로 확보한 판권면 자료**를 다룬다.

- `book_id`, `asset_type`(판권면 이미지 등), `acquisition_method`(직접 촬영, 제공받은 자료, 출판사 샘플 등)
- `source_url`, `storage_path`, `rights_review_status`, `public_allowed`

출판사가 배포한 PDF라도 모든 활용이 무조건 허용된 것은 아니다. 개인이 미리보기에서 수동 캡처했다고 해서 자동으로 공개 서비스에 복제할 권리를 얻는 것도 아니다. 원본의 내부 검수용 보관과 결과 데이터의 공개 가능 여부를 구분할 필요가 있다.

## 판권면 이미지와 크레딧 데이터는 공개 수준이 다르다

흐름은 **후보 등록 → 자료 출처 확인 → 허용 범위 검토 → OCR → 이름·직책 분할 → 사람 검수 → 출현 로그 저장 → 공개 판단**으로 나눌 수 있다. OCR 원본 전체 텍스트나 이미지가 곧바로 공개 DB로 전달되어서는 안 된다.

추출할 목표는 책 본문이 아니다. 원문에서 '책임편집 신성식', '디자인 안수진 기경란' 등 실제 크레딧의 이름·역할·위치와 날짜를 확인하고, 이를 최소한의 사실성 레코드로 저장하는 것이다. 같은 역할 아래 여러 사람의 이름이 나열되면 사람별 출현 레코드로 나눌 수 있지만, 줄바꿈·열 배치를 OCR이 잘못 읽을 수 있으므로 사람이 검수해야 한다.

자료원별 취득 유형을 `official_api`, `publisher_sample_pdf`, `partner_feed`, `user_provided_image` 등으로 분류할 수 있다. 다만 **유형명만으로 사용 허가가 입증되는 것은 아니다**. 파일·자료 제공자별 실제 허가, 용도, 보존기간, 재게시 여부를 기록해야 한다.

## robots.txt와 저작물 이용권의 차이

`robots.txt`는 자동 접근을 통제·안내하는 표준적 신호지만 저작권 허가 문서는 아니다. 그 파일의 접근 허용 여부와 서비스 계약상 이용 가능 범위는 별개의 층위다. 사람에게 웹페이지가 열리는 것도 스크립트의 무제한 수집을 허용하지 않는다.

미리보기 뷰어의 내부 이미지 주소를 추적한 대량 다운로드, 로그인·쿠키·세션 재현을 통한 수집, CAPTCHA·접근 제한·요청 한도의 우회, IP 회전이나 프록시를 이용한 탐지 회피 등은 기본 파이프라인으로 삼지 않는다. 서버 차단뿐 아니라 계약·권리·원본 품질 문제가 함께 따라오기 때문이다.

반면 허가가 확인된 출판사 제공 샘플, 직접 제공 자료, 공식 API는 별도로 평가할 만하다. 여기서도 **공개된 파일**과 **원하는 방식으로 재활용할 수 있는 파일**을 혼동하면 안 된다.

## 출판사 제공과 협력 모델

직접 제공 자료를 늘리는 방향도 있다. 편집자·디자이너·번역자와 제작자들의 이름이 판권면 이후 거의 검색되지 않는다는 문제를 설명하고, 본문 전체가 아니라 **크레딧을 구조화할 수 있는 자료와 사용 조건**만 제공받는 것이다. 작은 출판사나 독립출판 제작자부터 대화를 시작하는 방법이 제안되었지만, 실제 제휴가 성사되었거나 특정 출판사의 반응이 확인되었다는 뜻은 아니다.

이 길의 장점은 기술적 우회 없이 출처·허용 범위를 명시적으로 기록할 수 있다는 점이다. 동시에 어느 정도 응답이 올지, 얼마나 많은 판권면이 제공될지, 비용과 인력이 얼마나 들지는 실험 전에는 알 수 없다.

## 소규모 실험의 평가 기준

후보 도서 수와 실제 **판권면을 검수할 수 있었던 수**를 나누어 기록해야 한다. API로 식별된 도서, 미리보기를 확인한 도서, 판권면이 실제 표시된 도서, 저장·OCR 허용이 확인된 자료, OCR 성공 자료, 사람 검수 완료 자료는 각각 다른 집합이다.

확인할 지표는 ISBN 중복, 판권면 획득률, 사람 검수 소요, OCR 철자 오류, 역할 분류 오류, 출처별 권한 상태, 동일인 과잉 병합 등이다. 100권 정도의 작은 수동 표본부터 시작할 수는 있지만, 이것이 검증된 적정 규모라고 주장해서는 안 된다.

이 수집 경로의 목표는 도서 미리보기를 '긁는 것' 자체가 아니라 [이름의 출현을 기록하는 크레딧 아카이브](./credit-observation-archive.md)를 장기 운영할 수 있는 근거와 입력을 마련하는 데 있다.

## 검토 상태

이 글은 **기술적·정책적 설계 제안**이며, 개별 온라인 서점의 2026년 약관·로봇 정책·API 세부 필드·미리보기 실측 수집률, 저작권·개인정보 관련 구체적인 법률 판단을 새로 검증한 결과가 아니다.
