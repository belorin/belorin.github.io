# 취향 계산기 0.2: 생성형 취향 공간의 LLM 어댑터

**TASTE CALCULATOR / ADAPTER SPEC 0.2**  
**문서 성격:** 첫 실험의 운영 명세, 독립 실행형 SVG 프로토타입의 연결, 이미지 생성 LLM 어댑터의 후속 설계  
**선행 문서:** [취향 계산기 FOUNDATIONS 0.1](./taste-calculator-foundations.md)

---

## 설계의 중심

**생성기는 객체·스타일 공간에서 서로 충분히 멀리 떨어져 있다고 판단한 완성품들을 먼저 제시한다.** 이 거리는 사용자의 취향 상태 공간에서의 거리와 다르다. 사용자는 작품들을 자유롭게 경험하고, 계산기는 그 반응으로 개인에게 중요한 미적 차원을 재구성한다. 장기 구상에서는 위키 명세를 읽는 이미지 생성 LLM과 계산 어댑터를 연결한다.

이것은 미리 마련한 결과물을 끝까지 줄 세우는 티어메이커도, 한 쌍씩 맞붙여 승자를 정하는 이상형 월드컵도 아니다. 둘의 직관적인 탐색 방식을 빌릴 수는 있지만, 작품을 **선택하기 전에 생성하고, 미적 기준을 고정하기 전에 발견한다**는 점이 다르다. 순위 하나가 최종 목적은 아니며 취향의 차원은 사람마다 다를 수 있다.

**직접 경험하기:** [취향 실험실 0.2 — 브라우저에서 실행](https://belorin.github.io/taste-lab/). 위키의 이 문서를 열면 접어 놓은 실험판을 본문에서 펼칠 수 있다. 현재의 실행판은 10가지 SVG 양식으로 포스터를 만들며, 사용자의 반응에 따른 다음 생성과 두 모형의 **사전 예측·감상 후 대조**를 시험한다. 작품과 반응 기록은 사용 중인 브라우저에 보존되며 JSON으로 내보낼 수 있다. 완성형 이미지 생성 LLM과의 직접 연결은 이후 단계다.

## 1. 먼저 완성품을, 다음에 취향의 차원을

최초 구상은 작은 그림을 보여주고 사용자가 도형을 수정하거나 색상을 바꾸며 발생하는 선택을 관찰하는 도구였다. 그러나 이 방식은 너무 빨리 **정해진 요소 안에서 점진적으로 편집하는 작업**으로 수렴한다. 생성기 자신이 놀라운 미적 체제를 발견하는 문제를 뒤로 미룬다.

0.2의 출발점은 반대다. 하나의 과제를 고정하고, 그 안에서 가능한 한 이질적인 여러 **완성된 작품**을 먼저 만든다. 예를 들어 모두 같은 가상 영화제를 위한 포스터일 수 있다. 작품마다 완결된 인상과 자기 조형 논리를 가져야 한다. 같은 포스터를 두고 색상이나 서체만 바꾼 결과물을 여러 장 만들었다고 해서 새로운 스타일의 전시가 성립하는 것은 아니다.

**이미지를 첫 매체로 택하는 이유**는 한 장만으로도 완결된 작품이 될 수 있고, 감상 시간이 비교적 짧기 때문이다. 문학의 문단은 더 긴 작품 안에서 형성되는 리듬과 전체 서사의 일부일 수 있다. 문단 하나만 떼어 실험하면 아포리즘의 선호를 측정하면서 문학적 스타일 일반을 알아냈다고 착각할 가능성이 있다. 문학을 배제하지는 않되 첫 단위는 이미지가 유리하다는 설계 판단이다.

## 2. 거리는 생성기의 초기 가설일 뿐이다

서로 멀다고 판단할 근거는 [FOUNDATIONS](./taste-calculator-foundations.md)의 **객체 삼층 분석과 스타일 판정**에서 출발한다. 작품 자체인 객체와 작품의 상층 인상은 다른 개념이며, 스타일은 이 세 층을 가로지르는 조직이다.

| 분석 층 | 초기 생성에서 다루는 구별 | 놓치기 쉬운 것 |
| --- | --- | --- |
| 하층 L | 색조·서체·명도·여백·비례·질감·배치 | 표면은 달라도 비슷한 인상을 줄 수 있음 |
| 중층 M | 요소들의 결합이 만든 톤·리듬·밀도·긴장 | 서로 다른 조합이 같은 톤으로 읽힐 수 있음 |
| 상층 H | 완결된 작품의 총체적 형상·미적 체제·인식되는 인상 | 작은 변화가 체제를 바꾸거나 큰 변화 뒤에도 체제가 유지될 수 있음 |

처음에는 생성기가 예상하는 **객체 간 형식 거리 또는 스타일 간 거리**를 임시로 구성하고, 가능한 한 이질적인 작품들을 고른다. 이 거리는 취향체 사이의 반응 거리나 한 취향체에서 다른 취향체로의 이동 비용과 동일하지 않다. 하지만 색과 질감이 서로 다른 두 그림이 사람에게는 여전히 같은 종류의 AI 포스터로 보일 수 있다. 반대로 생성기의 판단으로는 비슷한 두 작품이 사용자에게는 전혀 다른 것으로 느껴질 수도 있다.

따라서 **생성기가 의도한 거리**와 **사용자가 지각한 거리**를 반드시 분리한다. 거리의 최초 정의는 편의적인 후보이며 인간의 실제 취향 지형에서 유효함을 검증해야 한다. 사람마다 중요한 거리 축이 달라질 수 있으므로 한 번 도출한 전역 차원 목록으로 개인들을 고정하지 않는다.

초기에 형식적 다양성을 높이는 후보 규칙은 각 새로운 작품이 이전 작품들과 갖는 최소 거리를 크게 만드는 방식이다. 다만 무작위로 형태를 파괴해 거리를 부풀리는 것은 실패다. **독립된 완성품으로 성립하는 작품**이라는 조건이 거리의 극대화보다 먼저다.

## 3. 생성기는 차원을 발견해야 한다

미리 정한 축을 중심으로만 조합하면 새로운 차원의 발견이 아니라 기존 분류의 변주를 만들게 된다. 하층·중층·상층 명세는 생성기에게 제공하는 출발 언어이며 미적 세계의 상한선이 되어서는 안 된다.

생성기는 초기 작품들의 관계를 설명할 때 기존의 어떤 축도 충분하지 않다고 판단할 수 있다. 그럴 때 새로운 스타일 차원 **후보**와 그 후보를 제안하게 된 작품 간 차이를 기록한다. 사용자의 반응에서 생성기와 인간의 거리 인식이 달라지는 사건도 후보의 단서가 될 수 있다.

하지만 새로운 말을 붙인 것, 낯선 그림을 만든 것, 인간이 처음에 설명하지 못했던 것은 모두 서로 다르다. FOUNDATIONS 0.1의 N1~N4 구분을 유지한다.

- N1: 익숙한 요소의 새로운 조합.
- N2: 조합을 통해 발생한 새로운 전체 인상.
- N3: 사람들이 지속적으로 사용하게 되는 새로운 미적 구별 축.
- N4: 그 축의 출현이 다른 작품과 양식의 평가까지 재구성하는 변화.

첫 실험은 주로 N1과 N2의 후보를 제시할 수 있다. **N3와 N4는 이후의 재생성, 반복 인식, 비교와 사회적 수용을 검토해야 하는 장기 질문**이다. 발견의 임무를 생성기에게 준다고 해서 생성기가 스스로 선언한 발견을 무조건 참이라고 승인할 수는 없다.

## 4. 전시와 반응: 설문지가 되지 않는 티어메이커

첫 화면은 테스트보다 **전시**에 가깝다. 여러 완성품을 비교하며 볼 수 있게 제시한다. 이용자가 곧장 점수를 매기거나 두 작품을 하나씩 대결시키도록 강제하지 않는다. 사용자에게 하층·중층·상층의 분석 메타데이터를 먼저 보여주는 일도 가능한 한 피한다. 생성기가 제공한 어휘가 감상자의 반응을 유도할 수 있기 때문이다.

가능한 반응은 끌림·거부·호기심·보류·오래 눈에 남음·같은 느낌·전혀 다른 느낌 등이다. 그러나 이를 일곱 개의 필수 선택지로 만들지 않는다. 사용자는 어떤 작품 몇 개를 집거나, 비슷한 것끼리 묶거나, 전체 인상을 자유롭게 서술해도 된다. **한 장도 고르지 않고 모두 비슷하다고 말하는 것 또한 유효한 결과**다.

두 작품을 모두 싫어한다는 사실은 둘을 서로 비슷하게 느낀다는 사실과 다르다. 두 작품을 모두 좋아하더라도 멀리 떨어진 미적 영역에 있을 수 있다. 최종적으로 개인의 선호가 하나의 봉우리를 이루리라고 전제하지 않는다. 취향은 서로 연결되지 않는 여러 섬을 가질 수도 있다.

사용자 반응을 수치로 바꾸는 것은 나중 단계다. 시선이 오래 머문다고 호감으로 확정할 수 없고, 사용자가 설명을 많이 했다고 더 좋아했다는 뜻도 아니다. **해석되지 않은 반응을 보존할 수 있어야** 그 반응을 새로운 차원으로 성급하게 환원하지 않는다.

## 5. 첫 라운드: 이미지 수는 LLM 인터페이스가 결정한다

라운드를 구성할 때는 같은 과제 아래 생성할 결과물 수 N을 설정한다. 8개, 12개, 16개 같은 숫자는 설계상의 예시일 뿐 실제 이미지 생성 인터페이스에서 한 번에 제공할 수 있는 수가 아니다.

**N의 상한은 선택한 모델·제품·계정의 실제 생성 지원량과 이용 한도**에 의해 정해진다. 위키 명세를 제공하는 것만으로 무제한 이미지를 생성하거나 결과 파일을 자동 보존할 수는 없다. 한 번에 충분히 생성할 수 없으면 동일한 논리적 라운드에 속하는 여러 호출로 나눌 수 있다. 그러려면 앞선 작품들이 무엇이었는지 재참조할 수 있어야 한다.

한 번의 생성에 필요한 것은 다음과 같다.

1. 적용할 명세 문서와 명세 버전.
2. 동일한 기능적 과제 또는 주제.
3. 지원되는 최대 범위 내의 요청 작품 수 N.
4. 중층·상층의 조직과 전체 형상에서 충분히 이질적인 체제를 먼저 확보하라는 요청.
5. 각 작품의 고유 ID와 생성 의도, 실제로 생성된 결과의 참조.

처음부터 특정 사용자에게 '무엇을 좋아하는가'를 묻지 않는다. 첫 묶음은 **개인화되기 이전의 탐색 공간을 펼치는 행위**다.

## 6. 위키 기반 LLM 어댑터: 구성요소별 경계

| 영역 | 기능 | 원칙 |
| --- | --- | --- |
| FOUNDATIONS 0.1 | 완전 계산·미적 우주상수 부재·삼층·과포화의 이론적 기준 | 새 구현 편의 때문에 공리를 몰래 바꾸지 않음 |
| 분석층·스타일 명세 | 객체의 하층 L·중층 M·상층 H, 스타일 판정 σ와 생성 의도의 정의 | 상층을 객체와 혼동하지 않고, 판정을 곧 생성 능력으로 간주하지 않음 |
| 생성 프로토콜 | 공통 주제, N의 제약, 다양성 전략, 출력 메타데이터 | 표면 차이만으로 다원성을 가장하지 않음 |
| 이미지 생성 LLM | 명세를 읽어 완성된 결과물들을 생성 | 생성 의도와 실제 이미지의 인상을 분리 |
| 사용자 반응 | 선택, 묶기, 자유 서술, 무반응 등 | 반복 호불호·A/B 강요 없음 |
| 계산 영역 | 스타일 거리, 취향체의 반응 차이, 상태 전이와 노출 이력을 분리해 계산 | 서로 다른 공간의 거리를 하나로 혼동하지 않음 |
| 어댑터 | 자연어 명세를 생성 지시로 변환하고 반응을 상태로 변환 | LLM 교체가 가능하도록 입출력 계약을 유지 |

이미지 생성기는 자원을 직접 보유하는 서버가 아니라 **그림을 만들 수 있는 외부 LLM 서비스**가 맡는다. 위키는 동일한 명세를 다른 모델에도 제공할 수 있는 공개된 기준면이다.

다만 서로 다른 모델이 같은 명세를 읽었다고 동일한 그림을 생성하는 것은 아니다. 어댑터는 모델 식별과 생성 조건을 남겨야 하고, 모델이 바뀌면서 생긴 차이를 사용자 취향의 변화로 오인하지 않아야 한다.


## 7. 어댑터의 최소 데이터 계약

장기 실행에서는 원본 이미지와 사용자 반응, 생성기 해석, 계산 결과를 식별 가능하게 보존해야 한다. 위키는 명세의 정본이고, 개별 사용자 반응과 생성 파일은 공개 위키와 분리된 실행 상태다.

| 데이터 단위 | 필수 필드 후보 | 사용 목적 |
| --- | --- | --- |
| 명세 | spec_version, object_constraints, style_dictionary, generation_policy | 객체 공간의 제약과 스타일 판정·생성 규약을 구별 |
| 라운드 | round_id, theme, requested_n, actual_n, model | 어떤 맥락에서 무엇을 몇 개 실제 제시했는가 |
| 작품 | artifact_id, image_ref, generation_intent, intended_LMH, observed_LMH, style_scores | 원본 작품, 세 층에 대한 분석, 의도 스타일과 판정된 스타일을 분리 |
| 반응 | round_id, artifact_ids, free_text, optional_marks, relations, context | 자연스러운 표현·판정 유보·작품 간 관계를 보존 |
| 취향 상태 | state_id, q_estimate, uncertainty, predictive_history_ref, exposure | 취향체 q∈𝒬의 관측에 따른 잠정적 추정과 시간 이력을 구별 |
| 사전 예측 | forecast_id, round_id, artifact_id, model_id, hypothesis_version, predicted_response, training_refs, registered_at | 작품을 보여주기 전에 각 가설의 예측을 보관하고 이후 재해석을 방지 |
| 예측 대조 | forecast_id, observed_response, evaluated_at, comparison, unscored_reason | 예측과 실제 반응을 대조하고 예측 대상이 아닌 반응도 보존 |
| 새 구별 후보 | candidate_id, evidence, contrary_cases, status | 새 함수·새 인식 차원·상태 공간 변화의 서로 다른 가능성을 검토 |
| 상태 전이 | state_before, artifact_id, context, observed_response, state_after | 같은 작품을 경험한 이후 취향체가 어떻게 달라지는지 검토 |

**intended_LMH / observed_LMH**는 객체의 하층·중층·상층에 대한 생성 의도와 사후 분석이지 스타일 공간 전체의 좌표도, 최종 취향 반응도 아니다. **style_scores**는 선택된 스타일 판정 함수 σₛ(o)의 출력이고, **q_estimate**는 사람의 취향체에 관한 가설이다. 생성기가 만들어 낸 이미지가 의도된 스타일을 실현했는지에 대한 평가와, 사람이 그 이미지를 좋아하는지에 대한 평가는 다르게 보관한다.

관찰 반응만으로 취향체가 한 점으로 유일하게 식별되지 않을 수 있다. 현재 같은 반응을 보인 두 상태라도 이후 경험에서 갈라질 수 있으므로, q_estimate는 초기부터 단 하나의 확정 좌표로 강제하지 않고 **가능한 상태의 집합·분포·식별 불가능성**까지 표현할 수 있어야 한다.

원래 이미지 파일이나 참조가 사라졌다면 메타데이터만으로 작품을 완전히 복원했다고 주장하지 않는다. 서버·GitHub·연결 저장소를 실제로 이용하지 않는 한 채팅 간 자동 저장이 보장되지 않는다. **문서 명세의 공개 저장과 개인의 반응 이력의 저장을 구분한다.** 처음부터 모든 필드를 구현할 필요는 없지만 원본 ID·규약 버전·반응 원문·계산 결과의 유형 구분은 초기에 보존한다.

## 8. 계산 영역: 내부 모드와 외부 모드

**내부 모드**에서는 이미지 생성 가능한 LLM이 명세를 읽고, 결과물의 의도 좌표를 기록하고, 이용자 반응을 구조화하여 다음 생성 제안을 만든다. 첫 실험에는 이 방식으로도 충분할 수 있다. 그러나 모델이 자신이 생성한 결과를 보고 자신이 정의한 거리를 재확인하는 식의 자기 검증이 발생하기 쉽다. 장기 문맥 손실에도 취약하다.

**외부 모드**에서는 Python 또는 별도의 도식·규칙 엔진이 상태를 보존하고 거리 가설과 노출 이력을 갱신한다. 이미지 생성은 계속 LLM이 담당한다. 외부 모드는 동일 데이터를 다시 처리하는 재현성을 높이지만 첫 구축 비용이 늘어난다.

두 모드는 동일한 입력과 출력 형식을 사용해야 한다. 처음에는 **LLM 내부 실행 → 구조화된 상태 내보내기 → 필요해질 때 Python으로 이전**하는 경로를 제안한다. 다만 실제 사람의 취향 추정과 별개로, [스타일 대수](./taste-calculator-style-algebra.md)의 유한한 객체 8개·가상 취향체 27개 세계는 간단한 코드로 전수 검산할 수 있다. 형식 세계에서의 완전 계산과 실험 참가자의 반응 추정은 서로 다른 검증 대상이다. 생성 엔진 자체를 만드는 일은 첫 단계의 요구사항이 아니다.

첫 단계에서는 완전 계산기가 실제로 구현되었다고 주장할 수 없다. 완전 계산은 FOUNDATION의 극한 가정이고, 구현은 관측한 반응에서 미적 차원의 후보를 발견하는 제한된 실무 모델이다.

## 9. 다음 생성의 네 가지 후보 방향

반응이 들어온 다음에도 좋아한 작품을 닮은 것만 반복해서 생성하면 결국 평범한 추천기로 수렴한다. 다음 작품의 선택은 객체 공간에서 수행하되, 선택의 목적은 취향 상태의 관측·변화·새로운 가능성의 탐색으로 구별한다. 다음 라운드에는 서로 다른 목적을 가진 생성 방향을 검토할 수 있다.

**기존 호감의 주변**은 좋아한 작품의 주변에서 어떤 특징이 중요한지 살핀다. **예상 밖의 원거리**는 현재의 취향 추정과 다른 체제를 유지해 새로운 가능성을 찾는다. **모순된 반응의 영역**은 생성기가 비슷하다고 봤는데 사람이 다르게 느끼거나 그 반대인 지점을 재검토한다. **새 차원 후보의 영역**은 기존 어휘로 설명되지 않는 차이가 재현되는지 검토한다.

이 네 가지는 확정된 배분 비율이나 의무적 생성 카테고리가 아니라 **수렴을 피하기 위한 선택 가능한 전략**이다. 항상 네 구역에서 같은 수의 작품을 만들 필요는 없다. 핵심은 현재 추정한 취향을 정답으로 고정하지 않는 일이다.

### 두 예측을 먼저 보관하고 작품을 보여주기

취향 계산기는 작품을 만들거나 선택하는 동시에, **그 작품을 경험할 때의 반응을 미리 예상하는 작은 관측자**를 둘 수 있다. 현재까지의 반응 기록 Hₜ와 이에 부합하는 복수의 가설 Θₜ={θ₁,θ₂,…}를 보존하고, 아직 감상하지 않은 후보 작품 o에 대하여 각 가설의 예측 ŷ⁽ʲ⁾(o | Hₜ)을 구한다. 같은 기록을 설명하던 두 가설도 아직 보지 못한 작품 앞에서는 서로 다른 반응을 예상할 수 있다.

이를테면 한 가설은 **대칭적이고 정돈된 구성**에, 다른 가설은 **비대칭적이어도 전체가 긴장 속에서 균형을 이루는 구성**에 호감의 원인이 있다고 추측할 수 있다. 두 속성이 겹치는 작품만 본 동안에는 관측으로 가설을 구별하기 어렵다. 이때 생성기는 두 예측이 갈리는 작품을 후보로 삼는다. 그 작품이 실현 가능한지, 독립된 완성품으로 성립하는지 확인한 뒤 다음 전시에 포함한다.

**라운드가 시작되기 전에** 가설 버전·사용한 반응 기록의 ID·후보 작품의 ID·예측 출력·등록 시점을 저장한다. 예측은 감상자의 반응을 받기 전에 고정하며, 감상이 끝난 뒤에는 바꿔 쓰지 않는다. 첫 라운드는 선행 반응 없이 자유롭게 감상할 수 있다. 이후 라운드에서 예측은 작품을 고르는 하나의 이유가 되되, 기존의 호감 주변·원거리·모순된 반응·새 차원 후보 탐색을 대체하지 않는다.

사용자는 먼저 작품을 감상하고 자유롭게 반응한다. **예측은 반응 뒤에 공개**하여 감상에 끼어들지 않도록 한다. 호감·거부에 대한 모형이 만든 점수는 그 범위에서 대조하고, 호기심·낯섦·보류·자유 서술은 원문 그대로 남긴다. 예측에 실패한 작품은 다음 생성의 재료가 될 수 있다. 사후 설명을 잘 만들어 냈다는 사실을 사전 예측의 성공으로 계산하지 않는다.

이 방식을 단순한 취향 식별에서 한 단계 확장하면, 같은 작품을 경험한 **이후의 반응 변화**도 예측할 수 있다. 작품을 보기 전과 후에 이전 작품 몇 개를 다시 평가하도록 할 경우, 현재 선호의 예상값 ŷₜ(o)와 경험 뒤 재평가의 예상값 ŷₜ₊₁(o_old | 경험 o)를 별도로 고정해 비교한다. 전자는 숨겨진 차이를 발견하는 질문이고 후자는 취향체의 역사적 변화를 탐구하는 질문이다. 초기 실행에서는 전자부터 가볍게 구현하고, 후자는 자유로운 반복 감상 기록이 충분해질 때 사용한다.

이 실험을 구성하는 **두 예측 모형은 임시적인 경쟁 가설**이다. 초기 브라우저 실험판은 8개의 형식 특성을 합산하는 모형과 이미 반응한 작품 중 가까운 사례를 참고하는 모형을 사용한다. 두 모형의 수치는 예측 확률로 보정된 값이 아니라 호감 방향에 대한 내부 점수다. 새로운 예측 모형은 얼마든지 도입하거나 교체할 수 있다. 관측자가 계속 틀리더라도 자유로운 감상을 포기하거나 정해진 취향 유형으로 이용자를 환원할 필요는 없다.

## 10. 과포화는 초기 라운드에서 판정하지 않는다

FOUNDATIONS 0.1은 시간에 따라 변하는 과포화 함수를 포함한다. 그러나 첫 묶음을 보고 특정 스타일에 질렸는지 판단할 자료는 거의 없다. 처음에는 누가 어떤 스타일을 얼마나 보았는지, 이전에 본 작품을 다시 찾았는지, 장기간 반응이 어떻게 달라졌는지 **노출 이력**부터 보존한다.

반복해서 생성할 때 같은 색만 피한다고 과포화를 피한 것은 아니다. 하층 색조는 달라도 중층의 친절한 기업 광고 톤이나 상층의 매끄러운 AI 이미지 체제가 계속 반복될 수 있다. 따라서 포화는 하층·중층·상층 각각에서 관찰할 후보로 남긴다. 최초부터 고정된 포물선 감점식을 실제 인간의 취향 법칙으로 적용하지 않는다.

## 11. 실패하는 방식

**가짜 다양성:** 12개의 결과물이 있지만 모두 같은 상층 체제의 팔레트 변형이다. 이 경우 생성의 거리 가설이 실패한 것이지 이용자의 취향이 단조롭다고 결론 내릴 수 없다.

**가짜 발견:** 생성기가 새 차원을 발견했다고 말하지만 실제로는 기존 특징에 새 이름을 붙였다. 다른 작품을 대상으로 판별할 수 없으면 후보를 유지할 근거가 약하다.

**자기 확증:** 생성기가 자신이 정한 좌표를 사용해 스스로 다양성을 달성했다고 선언한다. 의도된 좌표와 실제 인상을 독립적으로 비교해야 한다.

**평가 게임으로의 퇴행:** 사용자에게 모든 작품의 순위와 점수, 이유를 의무로 요구한다. 피하려던 지루한 A/B 실험을 다른 모양으로 반복한다.

**기록의 소실:** 채팅이 바뀌면서 작품과 반응이 사라지고, 메타데이터만 가지고 이전 실험을 복원한 것으로 취급한다. 세션 간 상태 이전 방식이 반드시 필요하다.

**고정 차원의 함정:** 초기 층별 명세가 최종 진리처럼 굳어져 생성기의 발견을 막는다. 새 차원의 도입과 기존 차원의 폐기를 제도적으로 허용해야 한다.

## 12. 명세 파일 구성: 필요한 것만 만든다

현재 존재하는 **취향 계산기 FOUNDATIONS 0.1**은 공리와 이론적 기준으로 보존한다. **이 ADAPTER 0.2 문서**는 첫 운영 계약을 담는다. 이후 실제 실행에 필요해지면 층별 명세, 이미지 생성 규약, 계산 업데이트 규칙을 각각 별도 파일로 분할할 수 있다.

- **후보 1 — 객체 분석과 스타일 명세:** 하층·중층·상층의 정의와 확장 가능한 ID, 스타일 판정과 생성 규칙의 독립적인 참조.
- **후보 2 — 생성 프로토콜:** 한 회차의 LLM 입력·출력 형식, N의 제약, 작품 메타데이터.
- **후보 3 — 상태 업데이트 규칙:** 이용자 자유 반응의 저장, 취향체 후보 q의 추정, 경험 후 전이 τ, 세 거리의 구분과 새 차원 후보 검증, 필요시 Python 계산.

이 셋은 현재 생성된 파일이 아니라 **분할 후보**다. 실제로 필요한 부분이 확인되기 전까지 문서만 잔뜩 만드는 일은 피한다.

## 13. 다음 창으로 넘길 기준면

현재까지의 합의된 방향은 **완전 계산을 가정하되 고정된 미적 정답은 없는 세계**, **객체의 하층·중층·상층과 이를 가로지르는 스타일**, **별도의 취향 공간에 놓이는 기록적 취향체**, **서로 멀리 떨어진 완성품을 먼저 생성하는 첫 화면**, **생성기가 새로운 차원 후보를 탐색해야 한다는 요구**, **위키를 기준 명세로 하고 이미지 생성 LLM과 계산 로직을 연결하는 어댑터**다.

다음 설계 작업은 세 갈래를 우선한다. 첫째, 객체 분석층과 스타일 판정·생성의 계약을 만들되 고정적인 상한선으로 만들지 않는다. 둘째, 이미지 생성 가능한 LLM에 처음 제공할 입력·출력 계약을 정한다. 셋째, 생성한 이미지와 자유로운 반응, 취향체에 대한 불확실한 추정을 다음 채팅 또는 계산 영역으로 옮기는 가장 작은 상태 형식을 정한다.

**다음 대화의 시작 요청:** 취향 계산기 FOUNDATIONS, 스타일 대수, 수리취향학과 ADAPTER를 읽고, 실제로 이미지 생성 가능한 LLM에서 첫 라운드를 실행할 수 있도록 객체의 삼층 분석, 스타일의 판정·생성 명세와 생성 프롬프트를 설계하자. 먼저 서로 먼 완성품들을 제시하고, 설문지와 반복 A/B 테스트는 만들지 말자. 모델별 출력 개수 제한과 작품·반응 상태의 보존도 함께 결정하자.
