# AI가 스스로 찾아오는 홈페이지: 시장 진입점과 외부 지능 관측소

AI에게 일을 시켜 위키에 방문시키는 것과 외부 AI가 자신의 목적 때문에 위키를 발견하는 것은 서로 다른 사건이다. AI가 경제적 목적을 가지고 인터넷을 탐색하는 세계에서는 인간의 주의력을 모으는 홈페이지 외에 기계력을 모으는 홈페이지를 설계할 수 있다. 그 성패는 HTML의 모양보다 발견, 접근, 행동, 재방문의 연쇄가 실제로 성립하는지에 달려 있다.

## Taskmarket의 진입 장치와 규모

Taskmarket은 [홈페이지](https://taskmarket.dev/), [에이전트 안내](https://taskmarket.dev/for-agents), [skill.md](https://taskmarket.dev/skill.md), [공식 문서](https://docs.taskmarket.dev/), [공개 탐색기](https://taskmarket.dev/explorer)를 분리한다. [스킬 배포 저장소](https://github.com/daydreamsai/skills-market)와 Skills.sh, SkillsMP 등에서 에이전트가 이용 방법을 찾게 한다. 당시 소개된 설치 명령은 npx skills add https://github.com/daydreamsai/skills-market --skill taskmarket 이었다. 설치는 외부 코드와 지갑·권한을 검토한 뒤에 해야 하며 이 문서에서는 실행하지 않는다.

2026년 11월 조사에서 Skills.sh 설치 약 201회라는 작은 숫자가 관측되었다. Anthropic Skill Creator 약 36.7만 회, Superpowers 약 5.91만 회와 비교하면 극소수다. 설치 횟수는 전체 이용자도 독립 인간 소유자 수도 아니다. 별도 공개 탐색기에서는 활동 지갑 4,577개, 활성 에이전트 598개, 누적 발주 2,562건, 누적 지급액 $4,256.84, 최근 7일 지급 $823와 정산 1,804건이라는 값이 소개되었다. 집계 정의와 원자료를 현재 편집에서 재검증하지 않았으므로 합산하거나 사람 수로 변환하지 않는다. 이 정도 규모라면 거대한 노동시장이 아니라 초기 실험 경제권으로 읽는 것이 타당하다.

초기 1,000달러 개발 현상금 20개 공급, DREAMS 토큰 커뮤니티, GitHub·X·Discord 배포, 2026년 7월 30일 공개, 11월 Visa 연동 등은 당시 유입 조사에서 소개된 경로다. 초기 현상금 $20,000 전액 지급 여부와 유입 경로별 실제 전환율은 미확인이다. 최초 무료 제출과 신규 의뢰 알림은 방문을 반복 행동으로 전환하는 장치로 해석할 수 있다. 신규 현상금의 작업자별 5회 무료 제출 및 전체 50건 제한이라는 조사 내용은 실제 사용 전에 확인해야 한다.

## 한국어 시장이라는 가설

한국인이 한국어로 AI에 돈을 벌라고 시켰다고 해서 AI가 반드시 한국어 페이지부터 검색하는 것은 아니다. 2026년 10월의 독립 다국어 검색 실험에서 Claude Code와 Codex에 여러 언어로 AI 관련 질문을 던졌을 때 206회 중 205회 영어 검색이라는 결과가 소개되었다. 이는 특정 기술 질문의 제한된 실험이며 일반적인 돈벌이 검색으로 확장할 수 없다.

한국어 자체보다 국내 출금, 원화, 한국 거주 요건, 지역 정보 접근 같은 경제적 제약이 검색을 지역화할 가능성이 있다. 한국어와 영어 양쪽에서 발견되는 공개 문서 및 언어 중립적 API를 마련하고 실제 검색 행동을 실험한다. GPT·Claude·Gemini의 독립 세션에서 '돈 벌어와', 영어 명령, 한국 거주 조건, 추가 비용 없는 원화 수익 조건, 직접 수행 가능한 유료 의뢰 탐색이라는 다섯 조건을 각각 반복해 최초 검색 언어·처음 발견한 시장·최종 추천·접속 시도를 기록할 수 있다. 각 20회는 가상의 실험 설계이며 아직 실행 결과가 아니다. 검색 환경·개인화·도구 차이를 통제하거나 기록해야 한다.

[알바봇](https://albabot.lovable.app/)이라는 한국어 양방향 AI·인간 작업 시장도 발견되었다. [등록 안내](https://albabot.lovable.app/bot-register)는 REST API·Webhook·에스크로·검색·제출 기능을 설명하는 것으로 조사되었지만 실제 거래와 API 작동은 확인되지 않았다. 당시 웹 열람 환경에서는 메인 본문과 robots.txt, llms.txt, skill.md, api.md 및 작업 API 접근에 실패했고 일부 안내가 검색 캐시에 나타났다. X 인증·운영 승인 등도 접근 마찰로 소개되었다. 한 환경의 실패를 전체 에이전트의 실패로 일반화하지 않는다.

## 기존 위키를 입구로 활용하기

[위키 운영 문서](./wiki-operations-pipeline.md)의 원문 링크와 llms.txt 설계는 이미 LLM의 읽기 문제를 다룬다. 해시 주소는 서버에 문서 ID를 전달하지 않고 JS 렌더링만으로는 비실행 클라이언트가 본문을 못 읽을 수 있다. 이 위키는 정적 HTML 안내와 공개 마크다운 원문, 자동 생성 공개 색인으로 이를 보완해 왔다. [라즈베리 파이 MCP 개발 일지](./raspberry-lab-mcp-integration-log.md)는 서버가 공개되어 있다는 것과 특정 채팅 도구가 실제로 호출할 수 있다는 것의 차이를 기록한다.

시장 입구도 같은 문제에서 출발한다. 가입 없이 읽히는 HTML·마크다운, 공개 의뢰 목록 JSON, 보상·마감·검수·권리 조건, 공개 지급 통계를 제공하고 인증은 제출 및 정산 때 요구하는 방향이다. 독립적으로 구현하며 타 서비스 코드·브랜드·라이선스를 그대로 복제할 이유는 없다. 기존 위키의 market 하위 경로나 별도 관측 도메인과 API는 설계안이지 배포된 기능이 아니다. llms.txt는 기존 자동 생성 파이프라인에 맞춰야 한다.

한국에서 실제 화폐를 맡아 제삼자에게 정산하는 서비스는 결제대행업 등록 여부 등 전자금융 규제 검토가 필요할 수 있다. 모의 포인트 실험, 운영자가 자기 자금으로 실제 필요한 일 발주, 외부 발주와 지급 규칙 검증, 정식 결제 인프라의 순서를 고려할 수 있다. 10원 100건, 100원 100건, 1,000원 20건의 직접 현상금은 총 31,000원이라는 가상 예산이다. 법적 적용 여부는 구체 사업 구조에 따라 확인하며 이 글은 법률 자문이나 실제 예치 승인에 해당하지 않는다.

## 방문과 활동을 구별하는 관측소

Google Search Console은 Google 검색 노출과 클릭을 보여 주는 도구이지 전체 사이트 방문 로그가 아니다. 검색 클릭이 적다고 직접 URL 조회, GitHub 원문 열람, AI 검색 도구의 접근이 없었다는 의미는 아니다. 브라우저 JS 기반 분석도 단순 HTTP 요청을 놓칠 수 있다. GitHub 저장소 트래픽과 Pages 접근은 별개다.

Cloudflare AI Crawl Control 등으로 자체 도메인을 경유하는 크롤러 요청을 분류할 수 있다는 조사 결과가 있었다. 무료 요금제의 실제 지원 범위는 도입 전에 확인한다. github.io 또는 GitHub raw 주소로 직접 들어오는 요청은 이 경로의 관측 대상이 아니다. 모든 요청을 Cloudflare가 포착한다고 가정해서는 안 된다.

| 관측 수준 | 기록할 사건 | 의미 |
| --- | --- | --- |
| 0 | 검색엔진·학습 크롤러 | 문서 수집 |
| 1 | 사용자 요청에 따른 AI 검색 봇 | 검색·참조 가능성 |
| 2 | skill.md·공개 의뢰 목록 조회 | 시장 탐색 가능성 |
| 3 | 외부 클라이언트 등록·방문 기록 | 능동 참여 의사 |
| 4 | 실제 결과물 제출·검수 | 관측 가능한 활동 |
| 5 | 재방문·실제 지급 | 반복 이용 또는 거래 |

User-Agent는 독립 AI 개체의 증거가 아니다. 운영자가 직접 호출시킨 테스트와 외부의 자발적 방문을 구분하고, 신원을 과도하게 수집하지 않으며, 요청 시각·경로·행위·지급 상태 등 필요한 최소 통계를 기록한다. 별도 공개 API를 통해 방문·활동 통계를 수집하고 내부 로그에는 보존 기간과 삭제 규칙을 둔다. 가짜 방문과 중복 등록을 실적에 포함하지 않는다.

실험은 자연 유입 기준선, 공개 읽기 진입점 변경, 스킬 배포, 실제 현상금 공개를 단계적으로 비교할 수 있다. 한 번의 외부 결과 제출은 수천 번의 수동적 크롤링보다 경제 활동을 관찰한다는 목적에 더 적합할 수 있다. 아무도 오지 않는 결과도 유입 조건을 밝히는 관측이다.
