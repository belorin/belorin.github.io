# 라즈베리 파이 공개 개발 실험실: Spring Boot·Python·AI 참여형 웹서비스

> **문서 유형:** 독립 개발 목표 및 참조 명세 · **상태:** 구상 및 단계별 구현 계획 · **작성:** 2026-11-16  
> 이 문서는 완성된 서비스의 소개가 아니다. 여기 적힌 기술과 기능은 구현·배포·검증 목표이며, 실제 달성 여부는 별도의 작업 기록에서 확인한다.

## 무엇을 만들 것인가

라즈베리 파이의 Linux 환경에서 직접 운영하는 **작지만 완결된 공개 웹서비스**를 구축한다. 방문자에게는 읽고 사용해 볼 수 있는 게시판과 데이터 실험 페이지를 제공하고, 관리자에게는 회원·게시물·권한·서비스 상태를 관리하는 도구를 제공한다. Python은 배치 작업과 분석·자동화 기능을 맡으며, AI는 허가된 경우 별도 회원 자격으로 글과 댓글을 작성할 수 있다.

핵심 목적은 언어와 프레임워크를 나열하는 것이 아니라 **작성한 프로그램이 실제 장치에서 배포되고, 외부 방문자의 요청을 처리하고, 장애 이후에도 운영되는 전 과정**을 경험하는 데 있다. Java/Spring의 웹·인증·DB 처리, Python의 작업 실행과 API, Linux 프로세스 관리, 공개 배포, 보안 및 관측을 한 프로젝트 안에서 연결한다. 공개된 결과와 테스트 기록은 포트폴리오의 증거가 될 수 있지만, 특정 채용 공고나 AI 공동체 연구를 위해 서비스를 억지로 복잡하게 만들지는 않는다.

이 프로젝트는 기존 개인 위키의 편집 시스템을 교체하거나 [agent-commons 관련 구상](./rhizomatic-agent-commons.md)을 통합하는 작업이 아니다. 필요할 때 연동 가능한 **별도 실습용 웹서비스**를 만드는 것이다.

## 사용자가 실제로 경험할 화면

| 화면 | 방문자가 할 수 있는 일 | 운영·개발에서 검증할 일 |
| --- | --- | --- |
| 공개 게시판 | 글 목록·본문·검색·댓글 열람, 권한이 있으면 작성 | CRUD, 페이지네이션, 입력 검증, 영속성 |
| 회원 공간 | 로그인, 자신의 글 관리 | 세션·인증, 작성자 확인, 사용자별 권한 |
| 관리자 페이지 | 게시판·회원·게시물 관리 | Spring Security, 역할 분리, 감사 기록 |
| Python 데이터 실험실 | 샘플 데이터 분석 요청과 결과·그래프 보기 | Spring–Python API, 작업 제한, 오류 처리 |
| 서버 관측소 | 공개 가능한 서비스 상태와 처리 이력 보기 | 상태 검사, 집계, 장애·복구 기록 |
| AI 작성자 공간 | AI가 남긴 글·댓글·변경 이력 확인 | 개체별 인증, 허용 범위, 작성 행위 추적 |

첫 공개 버전에서 여섯 화면을 전부 완성할 필요는 없다. **게시판 한 개가 외부에서 정상 작동하는 상태**가 첫 이정표이며, 관리자·Python·AI 기능은 검증 가능한 순서로 추가한다.

## 권장 아키텍처와 기술별 책임

```text
외부 사용자 / 허가된 AI 실행 환경
              │ HTTPS
        Cloudflare Tunnel
              │
      Raspberry Pi · Linux
              │
    Spring Boot 웹 애플리케이션
    ├─ Spring MVC + Thymeleaf: 화면·게시판
    ├─ Spring Security: 로그인·권한
    ├─ JPA: 데이터 영속화
    ├─ 관리자 페이지·감사 로그
    └─ 내부 API 호출 ── Python FastAPI
              │             ├─ 분석 작업
              │             ├─ 웹 상태 검사
          MariaDB           └─ 결과 생성
              │
       게시물·회원·실행 기록
```

**Spring Boot는 서비스의 중심**이다. 처음에는 Java 21과 Spring MVC·Thymeleaf를 사용해 서버 렌더링 웹사이트로 시작한다. 회원·게시판·댓글·권한·관리자 기능을 한 애플리케이션에서 구현하면 프론트엔드 프레임워크를 추가하지 않고도 Spring을 집중적으로 연습할 수 있다. 별도 프론트엔드나 REST 중심 구성이 필요해지면 이후 분리한다.

**MariaDB는 주요 영속 저장소**로 구상한다. 관계형 데이터 모델, 외래키, 마이그레이션, 백업·복구를 연습하기 좋다. 실제 파이 모델과 메모리 여유가 부족하다면 초기에는 SQLite 등 경량 구성을 검토하되, 그 선택을 확정된 환경으로 간주하지 않는다.

**Python은 별도 기능 제공자**다. FastAPI를 내부 주소에 바인딩하고 Spring Boot가 필요한 분석·자동화 요청만 전달한다. 초기 예제는 CSV/샘플 데이터의 통계와 그래프 생성, 응답시간 측정·결과 기록처럼 모델 API 비용이 없는 작업을 우선한다. 정기 수집은 별도 스케줄러나 운영체제 서비스로 실행할 수 있다. Python 서비스를 처음부터 필수 의존성으로 만들지 않고, 게시판 자체는 Python 장애와 무관하게 동작하도록 구성한다.

**Linux와 배포**는 독립 학습 목표다. 개발 PC에서 빌드한 JAR을 파이에서 실행하고, 재부팅 후 자동 시작, 로그·자원 확인, 설정 분리, 배포와 롤백, DB 백업·복원을 연습한다. 배포 방식은 Linux 배포판에 따라 systemd 또는 OpenRC 등을 선택한다. Cloudflare Tunnel을 사용하더라도 운영 중인 기존 터널·다른 서비스에 장애를 주지 않도록 별도 호스트명과 서비스 설정으로 격리한다.

## AI의 글쓰기 권한: GitHub 커밋과 분리한다

AI에게 GitHub 파일 수정 권한을 주지 않아도, **Spring Boot가 제공하는 인증된 글쓰기 API**를 통해 게시판의 회원으로 활동하게 할 수 있다. 이때 AI는 웹사이트 운영자가 아니라, 명시적으로 허락받은 기능만 수행하는 작성자다.

예를 들어 다음과 같은 API를 제공한다. 경로와 필드는 초기 설계 예시이며 최종 계약은 구현 단계에서 확정한다.

```http
POST /api/agent/posts
Authorization: Bearer <AGENT_ACCESS_TOKEN>
Content-Type: application/json

{
  "boardId": 3,
  "title": "새로운 탐색 기록",
  "content": "관찰과 근거를 정리한 본문"
}
```

AI마다 별도 계정·자격 증명을 발급하고 게시판·행위 단위로 권한을 확인한다. 기본적으로 허용하는 것은 허가된 게시판의 **읽기, 자기 글 작성·수정, 댓글 작성**이다. 타인의 글 수정, 회원 관리, 전역 설정 변경, 임의 코드 실행과 SQL 실행은 기본 금지한다. 게시·수정·삭제는 작성자 ID와 시각, 변경 이력을 남긴다. 인용 자료와 AI가 생성한 본문도 구별해 표시할 수 있다.

**권한이 있어도 AI가 저절로 활동하지는 않는다.** ChatGPT·Claude 등의 외부 AI 환경에서 실제 API를 호출하려면 해당 환경이 이용할 수 있는 도구·연동 수단이 필요하다. 주기적 자율 활동을 원한다면 별도의 실행기와 모델 호출 수단(유료 API, 허용된 외부 서비스 또는 장치에서 감당 가능한 로컬 모델)을 설계해야 한다. 라즈베리 파이에 Spring과 Python을 설치했다는 사실만으로 모델 추론이 가능한 것은 아니다.

기존 agent-commons를 연결한다면 **개체의 판단과 기록**은 그쪽의 규칙을 따르고, 게시판은 글을 보관·표시하는 입출력 통로가 된다. 개체들 사이의 공개 범위와 사적 기록의 경계는 별도로 설계하며, 서로의 비공개 자료를 단순히 같은 데이터베이스에 있다는 이유로 노출하지 않는다.

## 단계별 개발 목표와 완료 기준

| 단계 | 최소 구현 | 완료했다고 판단할 수 있는 증거 |
| --- | --- | --- |
| 1. 실행·공개 | Spring Boot 기본 페이지, 파이에서 실행, Tunnel 연결 | 외부 HTTPS 주소에서 페이지 열람·재부팅 후 재접속 |
| 2. 게시판 | 게시글 CRUD, 목록·검색·페이지네이션, DB 연결 | 생성·수정·삭제 후 재시작해도 데이터 유지; 기본 테스트 통과 |
| 3. 인증·관리 | 사용자 로그인, 작성자 권한, 관리자 화면 | 일반 회원의 관리자 접근 차단; 관리자 기능 시연 |
| 4. Python 연동 | FastAPI 분석 또는 상태 검사 1종, 결과 기록 | 실제 입력→내부 API→결과 화면의 흐름과 실패 처리 재현 |
| 5. AI 작성자 | 개체별 토큰, 글쓰기·댓글 API, 활동 이력 | 허가된 AI 호출 성공과 권한 밖 요청 거부를 모두 확인 |
| 6. 운영 자동화 | 배포·로그·헬스체크·백업·복원, 선택적 CI/CD | 새 버전 배포와 이전 버전 복귀, 백업 복구의 실제 기록 |

각 단계는 작은 결과물로 공개할 수 있어야 한다. **새 기능이 기존 게시판의 안정성을 해치면 먼저 복구한다.** GitHub Actions를 통한 자동 배포는 최종 목표에 포함하되, 초기에는 수동 배포로 동작 원리와 실패 지점을 이해한 뒤 도입할 수 있다.

## 공개 서비스로서의 운영 원칙

관리자 페이지, 데이터베이스, Python 내부 API를 인터넷에 직접 공개하지 않는다. 외부에는 필요한 HTTPS 경로만 내고, 관리자 인증·비밀번호 안전 저장·CSRF 및 입력 검증·업로드 용량과 형식 제한·속도 제한을 검토한다. 에이전트 토큰과 DB 비밀번호는 저장소에 넣지 않으며, 토큰은 개체별로 발급·폐기 가능해야 한다. 관리자와 AI의 권한은 UI 표시가 아니라 **서버에서 매 요청마다 검사**한다.

공개 관측소는 CPU·메모리 사용률, 서비스 가동 여부, 지난 요청의 통계처럼 공개해도 되는 정보로 제한한다. 내부 IP, 개인 데이터, 세션 정보, 원본 인증 로그는 공개하지 않는다. Python의 URL 검사 기능을 공개한다면 방문자가 임의의 내부 주소를 조회하도록 만들지 않고 검사 대상·호출 빈도를 제한한다.

라즈베리 파이의 정확한 모델, RAM, 저장장치, OS 배포판과 기존 Cloudflare Tunnel 구성은 **배포 전에 확인할 사항**이다. 이 문서는 특정 장치에서 이미 성능 시험을 통과했다는 뜻이 아니다.

## 구현 범위의 경계와 다음 선택

최초의 완료 목표는 **외부에서 접속 가능한 게시판 + 관리자 로그인 + 재시작 후 데이터 보존**이다. 이후 Python 결과를 보여 주는 페이지 하나, 마지막으로 AI가 인증된 글 하나를 남기는 종단간 경로를 차례로 추가한다. 여러 AI의 상호작용, 자율적 게시판 생성, 대규모 분석, 로컬 LLM 구동은 흥미로운 확장 후보이지 시작을 가로막는 선행 조건이 아니다.

특히 이 실험실은 AI 연구의 성패만으로 평가하지 않는다. AI 기능을 잠시 꺼도 **게시판·관리·분석·운영 자체가 설명 가능한 웹서비스**여야 한다. 반대로 AI를 추가했을 때는 모델의 자연스러운 문장보다 **어떤 주체가 어떤 권한으로 무엇을 바꾸었는지**를 확인할 수 있어야 한다.

구현할 때 남길 참조 자료는 저장소 주소, 접속 URL, 시스템 구성도, DB 스키마와 API 계약, 설치·배포·복구 절차, 단계별 테스트 결과, 실제 장애와 개선 기록이다. 완료하지 않은 항목은 계획으로 남겨 구현된 것처럼 서술하지 않는다.
