# 기계력과 지식 압착 아키텍처 (Knowledge Press) v0.1

목적: 지속적으로 공급되는 모델 실행 자원을 인간의 독서 비용 절감과 새로운 이해에 전환한다. 보고서·통계 수집량이나 글의 길이가 아니라 개념과 설명의 변화가 성과다. [기존 보고서 교차 탐사](../../wiki/cross-institutional-report-discovery.md)는 증거 관리의 참고 자료이며 추가 방법론 연구의 자동 대기열이 아니다.

## 다섯 층과 저장소

| 층 | 역할 | 바닥경제 파일 |
| --- | --- | --- |
| L0 | 원자료 위치, 구체적 통계·사례·근거, 검증 기록 | wiki/korea-bottom-economy-2026.md 및 관련 근거 문서 |
| L1 | 한 문장 개념, 안정적 ID | wiki/korea-bottom-economy-concept-compression.md §1 |
| L2 | 여러 세션의 문단과 개념 체인, 조건·반례 | 같은 문서 §2–4 |
| L3 | 현재 설명체계, 경쟁 가설, 결론 | 같은 문서 §5 |
| L4 | 인간이 읽는 독립적 원고 | wiki/korea-bottom-economy-reading.md |

제어 상태는 [bottom-economy/state.json](./bottom-economy/state.json) 하나다. 원본을 복제하지 않는다. L0은 누적·정정하고 L1–L4는 현재의 최선으로 재편한다. 개념을 병합·폐기할 때 ID와 이유를 짧게 남기고 과거 전문은 Git 이력에서 복구한다. 위키의 일반 증보 규칙을 변경하지 않으며 이 실험의 파생 압축본에만 축소·재집필을 허용한다. 원자료의 유효한 정보는 삭제하지 않는다. 공개 저장소에 사적 증언 원문·대화 ID·비밀을 저장하지 않는다.

## 회차 — 한 번의 기계력 공급

실행기는 [RUN.md](./RUN.md)를 최신 main에서 읽고 정확히 한 번의 상태 전이를 수행한다. 스케줄러는 시계일 뿐이다. 상태와 실행규칙을 외부화하여 ChatGPT, 다른 모델, 향후 API 실행기가 같은 계약을 이용할 수 있게 한다.

1. 목적, L3의 현재 결론, 최근 상태를 읽는다.
2. 가장 중요한 설명의 빈틈 또는 개념의 충돌을 고른다.
3. 연산 하나를 선택하고 필요한 층만 읽는다.
4. 실제 생각의 결과를 한 문장으로 남긴다. 기존 문장을 더 잘 고친 것도 성과다.
5. 관계나 결론이 변하면 해당 층을 재편한다. 독자의 이해가 좋아질 때만 L4를 갱신한다.
6. 변경 사항과 상태를 검증하고 저장한다. 변화가 없으면 왜 없는지 짧게 기록한다.

## 서로 다른 연산

- 탐사 explore: 개념의 판별에 필요한 자료만 가져온다. 근거 축적만으로 새로운 개념을 주장하지 않는다.
- 압축 compress: 여러 근거 또는 회차를 한 문장·문단으로 재구성한다.
- 결합 combine: 서로 다른 개념에서 새로운 관계·설명·예측을 도출한다.
- 전이 transfer: 다른 영역에 개념을 적용하며 성립 조건의 차이를 드러낸다.
- 반증 challenge: 가장 강한 반례·경쟁 가설을 검토하고 개념을 제한·기각한다.
- 총합 synthesize: 개념 간 관계를 재편하여 현재 결론을 다시 쓴다.
- 망각 prune: 중복·빈 개념·무의미한 질문을 병합하거나 폐기한다.
- 저술 write: 독서용 원고의 중심 논제와 흐름을 개선한다.

탐사와 반증은 구별한다. 반증은 기존 근거와 논리만으로도 가능하다. 새 사실이 없어도 합성적 추론을 할 수 있으나 그것은 가설이다.

## 제어 정책 — 설계의 무한 재귀를 막는다

처음 20회는 파일럿으로 삼는다. 최근 6회에서 외부 탐사는 최대 2회, 자료 검색을 수반한 다른 연산까지 포함하여 최대 3회. 동일 연산을 3회 연속 하지 않는다. 최소 2회는 외부 검색 없이 개념 결합·압축·총합·망각을 수행한다. 긴급 정정은 예외로 기록한다. 이 비율은 실험값이며 최적이라는 주장이 아니다. 운영 중 새 방법론 절을 계속 작성하거나 아키텍처를 자율 변경하지 않는다. 파일럿 종료 시 실제 전후 차이를 비교하고 사용자에게 검토를 요청한다. 상태는 최근 6회만 보존하고 전체 이력은 Git을 이용한다.

독서용 원고는 기본 2,500~5,000자, 상한 6,000자(마크다운 포함). 길이 자체가 목표는 아니며, 중요한 근거는 링크로 남긴다. 개념 페이지는 기본 20개 이내의 활성 개념과 8개 이내의 활성 체인으로 유지한다. 꼭 필요하면 병합·퇴역부터 검토한다. 개념의 이름을 바꾼 것만으로 발전으로 세지 않는다.

## 평가

독서용 원고의 이전 판과 현재 판을 같은 독서 시간으로 비교한다. (1) 새 설명 또는 구별, (2) 연결의 설명력, (3) 반례에 따른 수정, (4) 추론이 근거로 내려가는 경로, (5) 읽기 비용의 변화. 자료 수·커밋 수·개념 수를 성공 점수로 삼지 않는다. 전후 차이가 없는 회차도 허용하되 반복 무변화는 연산 전환 신호로 사용한다. 20회 종료 시 이 다섯 차원과 대표적인 변화·실패를 짧게 보고하고 이후 회차는 연구 편집을 멈춘다.

## 실행기 계약 / API 이행

현재는 사람처럼 GitHub 파일을 읽고 수정하는 프롬프트 기반 실행기다. 향후 API에서는 세 인터페이스로 제한한다.

- read_state(project): 상태 JSON 및 각 층의 경로·현재 blob 식별자를 읽는다.
- propose(state, operation): 근거를 읽고 변경 파일·한 문장 결과·반증 조건을 반환한다. 저장하지 않는다.
- apply(expected_revision, changes): 현재 revision을 비교하고 허용된 경로의 변경을 원자적으로 커밋한다. 충돌이면 재읽고 재평가한다.

API 구현은 이 파일럿에서 하지 않는다. 먼저 실제 회차에서 유용한 변화가 생기는지 확인한다. GitHub 커넥터가 원자적 커밋을 지원하면 이용하고, 순차 쓰기만 가능하면 RUN.md의 복구 절차를 따른다. 자동 생성물과 기존 다른 프로젝트는 변경하지 않는다.
