# 취향계산기: L1–L3 연속 실험 프로토콜 (초안 0.1)

이 문서는 브라우저의 독립 실행형 취향 실험실과 별개로, **ChatGPT 대화에서 생성한 인물 캐릭터 이미지에 대해 사용자가 자연어로 반응하는 실험**을 장기적으로 잇는 프로토콜이다. 배경 이론은 [취향 계산기 FOUNDATIONS](../../wiki/taste-calculator-foundations.md)와 [취향계산기 어댑터](../../wiki/taste-calculator-adapter.md)이며, 직접 실행 가능한 이전 프로토타입은 [한 사람씩](./README.md)이다. 기존 이론의 하층 요소 L·중층 스타일 M·상층 객체 H와 여기의 **시스템 운영층 L1–L3는 서로 다른 구분**이다.

## 왜 세 층인가

ChatGPT 이미지 생성은 눈앞의 사례를 잘 따라간다. 개별 작품에 대한 호감 하나가 다음 생성에서 얼굴·머리·의상·화풍·구도까지 재현하는 신호로 과잉 해석되면, 탐색을 시작하자마자 서로 비슷한 이미지가 연속된다. 호감이 높다는 것은 **하나의 봉우리를 발견했다는 관측**이지, 그 봉우리에 머물라는 명령이 아니다. 스타일의 반복은 취향의 실제 과포화일 수도 있고, 생성기 자체의 모드 붕괴일 수도 있다. 사용자의 취향 변화를 추정하기 전에 이 둘을 구별해야 한다.

| 운영층 | 담당 | 보존해야 할 것 | 실패 징후 |
| --- | --- | --- | --- |
| **L1: 채팅 생성·감상** | 이미지 한 장 생성 → 사용자 자연어 반응 → 다른 이미지 한 장 | 관측된 반응, 이미지의 식별 가능 단서, 그 전에 사용한 생성 전략 | 똑같은 얼굴·모델 포즈·질감을 두고 장면만 교체 |
| **L2: 탐색 상태·가중치** | 반응에서 국소 선호·회피·미확인 가설 추출, 중복과 포화 위험 관리, 다음 탐색 모드 선택 | 다봉우리 가설, 가설별 확신도와 근거, 이미지 노출 기록, 선택 정책과 이유 | 긍정 응답을 '복제', 부정 응답을 '취향 자체의 거부'로 즉시 환원 |
| **L3: 위키·코드·프로토콜** | 정의·데이터 계약·업데이트 원리·실패 사례·구현 버전·재현 실험 관리 | 개정 가능한 명세, 상태 스키마, 검증 가능한 구현과 테스트 | 세션이 끊기면 실험의 규칙과 상태가 함께 소실 |

세 층은 서로 선형적으로 종속되지 않는다. L3는 L2를 해석하는 규약을 제공하고, L2는 L1의 생성 전략을 제공한다. L1의 관측은 L2에 업데이트 후보로 들어오며, 반복적으로 확인된 설계상의 발견만 L3의 규약 개정 근거가 된다. **L2의 추정은 장기 기억에 쌓인 사실과 동일하지 않다.**

## 인터페이스: 사용자에게는 이미지, 기록은 뒤에

기본적으로 채팅에는 **한 장의 생성된 인물 이미지**만 제시한다. 설명·점수·장황한 구분 질문은 노출하지 않는다. 사용자는 '예쁘다', '매력적인데 비슷하다', '건장해 보인다', '그저 그렇다'처럼 자유롭게 반응한다. 이 한 문장은 여러 관측으로 해석될 수 있으나, 해석이 실제 감정의 확정값으로 위장되어서는 안 된다. 생성과 평가의 초점은 완성된 형상·작품의 총체적 인상이지 눈·코·색 등 하나씩 통제하는 실험이 아니다.

**응답을 마친 후 내부적으로 수행하는 최소 절차:**

1. 반응을 원문 대신 최소한의 **비인용 의미 기록**으로 구성한다. 미적 호감, 인상/서사, 반복 지적, 생성 포즈나 도상에 대한 불만은 서로 다른 종류로 구분한다. 관찰된 내용과 모델이 추정한 내용은 분리한다.
2. 현재 이미지와 직전 이미지의 **총체적 유사성**을 평가한다. 시각적 도상·얼굴·머리·의상·질감·인물 배치·시대감·정서적 체제의 재사용을 검토한다. '무슨 축이 세 개 바뀌었는가'는 보조 지표일 뿐, 전체적 체제가 여전히 같으면 원거리 탐색으로 인정하지 않는다.
3. L2의 여러 국소 봉우리 가설을 갱신하거나 새 후보를 개설한다. 첫 몇 번의 호감으로 단일 중심점을 확정하지 않는다. '호감 / 아름다움 / 새로운 영역 탐색 요구'는 함께 성립할 수 있다.
4. 이미지 제시 정책을 결정한다. 초반부는 취향 봉우리의 존재를 *찾기 위해* 원거리 생성에 높은 비중을 두되, 70% 등의 비율은 **임시 정책 매개변수**이지 인간 취향의 사실이 아니다.
5. 다음 이미지 한 장을 생성한다. 이전 이미지로부터 얼굴·화풍·옷을 복제하여 재합성하는 방식이 아니라 **자기완결적인 새로운 인물 형상**을 만든다. 후보 생성 단계와 사용자의 취향 추정은 별도 기록으로 남긴다.
6. 여러 차례 반복 시 익숙해짐/피로를 물어야 한다면 자연어 반응 속에서 자발적 표현이 나오는지를 우선 관찰한다. 단지 이미지가 닮았다는 이유로 '사용자가 이미 질렸다'고 단정하지 않는다.

## L2: 무엇에 가중치를 두는가

L2는 사용자의 실제 신경계나 모델 파라미터에 접근하는 과정이 아니라 **명시적이고 가역적인 추정 상태**다. 각 항목의 수치는 통계적 보정 전에는 점수만으로 의미가 없으므로 확신도·근거 수·관측 범위를 함께 둔다.

- `preference`: 작품에 대한 현재 선호의 국소 모드 후보. 여러 개의 봉우리를 허용한다.
- `avoidance`: 작품의 불호와 **생성 방식 자체의 결함**을 구분한다. AI 초상화 포즈 클리셰에 대한 불만은 전체 인물군의 거부가 아니다.
- `saturation`: **관측된 반복 노출**과 **보고된 질림**을 다른 변수로 둔다. 반복 노출만으로 지루함을 추정하지 않는다.
- `exploration`: 선호 부근, 원거리, 모순, 새 체제 후보를 번갈아 탐색하며, 초반에는 원거리의 가중치를 높게 둔다.
- `uncertainty`: 취향을 잘 모른다는 것과 생성기가 다양한 표본을 만들지 못한다는 것을 구분한다.
- `generation_failure`: 직전 이미지와 같은 얼굴·헤어·복장·프레임·질감이 반복된 **이미지 생성기의 실패**를 별도 기록한다.

개념적 탐색 점수의 한 예는

```
priority(x) =
    local_affinity(x)                     # 여러 선호 봉우리의 국소 지지
  + exploratory_value(x)                  # 미관측·원거리·반례 후보
  - repetition_pressure(x | recent)       # 이미지가 비슷하게 반복될 위험
  - generator_cliche(x)                   # 생성기 자체의 모델 포즈/평균 얼굴 편향
```

이며 이 수식을 곧바로 자동 적용하는 코드나 검증된 인간 취향 모형으로 취급하지 않는다. 실제 이미지 생성에서는 후보를 미리 여러 장 만들어 비교할 수 없다면, **다음 생성 요청의 설계 의도**를 선언하고 결과가 그 의도에 부합하는지 사후 평가한다. 사후 결과를 이미 예측했던 것으로 기록하지 않는다.

### 업데이트의 비대칭성

호감 표현은 해당 이미지에 대한 강한 양의 증거가 될 수 있지만, 그 이미지의 **모든 요소**에 높은 가중치를 준다는 뜻은 아니다. 반대로 '다른 이미지와 같다'는 지적은 **중복 판정에는 강한 증거**지만 해당 체제 전체에 대한 부정 반응은 아니다. 따라서 보통의 관측 갱신은 아래처럼 비대칭적이다.

- 새로운 미적 호감: 특정 사례의 반응만 기록. 국소 선호 후보를 생성하되 취향 전체의 인과 요소는 미정.
- 모델 포즈 클리셰 지적: *생성품질·선정 정책* 가중치를 수정. 이미지의 나이·성별·의상에 대한 거부로 확대하지 않음.
- 다른 이미지와 너무 유사하다는 지적: *탐색 실패*로 기록하고 원거리 탐색 압력을 올림. 이때 반복 노출량은 올라가지만 사용자의 포화 상태는 여전히 미정.
- 같은 종류를 여러 번 좋아함: 해당 국소 영역의 지지가 강화되나, 그것이 다른 봉우리의 부재를 의미하지 않음.
- 반복 노출 뒤 '이제 질린다': 그때 비로소 사용자가 보고한 포화 증거가 추가됨. 이후 재노출에서 회복할 가능성도 허용.

## 보존과 승격

**L1의 원본 이미지는 자동으로 위키에 남지 않는다.** 채팅 내 생성물은 대화에 연결되어 있어도 위키에 저장했다고 가정하지 않는다. 그에 따라 어떤 평가가 정확히 어떤 이미지에 관한 것이었는지 미래의 다른 세션에서 완전히 복원하지 못할 수 있다. L2에 보존할 대상은 관측 이벤트의 핵심 의미, 이미지를 묘사하는 충분한 요약, 가설·가중치의 버전, 정책 결정과 생성기 실패의 분리다.

**ChatGPT 메모리 기능은 임의 JSON 상태를 정확히 기록·갱신하는 신뢰성 있는 데이터베이스로 취급하지 않는다.** 이 대화에서 메모리의 실제 보존 결과를 검증하거나 수치 필드를 강제할 수 없다. 따라서 정확한 상태 보존의 기준은 다음과 같이 둔다.

- 대화 중에는 현재의 L2 상태를 이용해 이미지 생성 전략을 선택한다.
- 세션 사이 연속성을 보장하려면 [`state.schema.json`](./state.schema.json)에 따른 **휴대 가능한 상태 스냅샷**이 필요하다. 공개 위키에는 규약과 가상의 예시만 올리고 실제 개인 반응은 사용자의 명시적인 공개 승인 없이 공개 저장소에 올리지 않는다.
- 새 세션에서는 해당 스냅샷을 읽고 현재 대화에서 접근할 수 있는 이미지·반응 범위와 대조한다. 이전 이미지의 시각적 분석 결과를 원본 없이 새로 계산했다고 주장하지 않는다.
- 관측 없이 후속 요약이 이루어지면 **미검증 후속 요약**으로 남기고 가중치를 확정하지 않는다.

L3의 영속적인 버전 관리 대상은 공리·단위 계약·알고리즘·테스트·실패의 비식별적 분석이다. L2의 사용자별 상태는 **정본이 필요하되 공개 위키에 함께 넣을 필요는 없다**. 개인 기억과 공개 명세를 분리해야 한다.

## 현재 실험에서 얻은 개발상의 결과

초기 이미지 생성 시험에서, 개별 작품에 대한 긍정 반응 뒤에 비슷한 인물상·옷·회화 양식이 계속 나타났다. 세 번째 이미지의 차이가 크게는 배경과 동작에 머물렀다. 이는 **호감 이후의 생성 모델이 이전 객체를 보존하는 쪽으로 수렴할 수 있다**는 실패 사례다. 이 실패는 다음 작품을 만들 때 같은 인물의 부분 변형을 피하는 정책의 근거가 된다. 하지만 인간의 선호 봉우리 수, 인간의 과포화율, 특정 속성에 대한 인과적 선호를 증명하는 자료는 아니다.

## 다음 개발 기준

1. 채팅에 최적화된 **한 장 생성 → 자연어 반응 → 다음 한 장**을 기본 UI로 유지한다. 별도의 브라우저 앱은 선택 가능한 기록·검증 도구이지 채팅 실험을 대체하지 않는다.
2. L2 상태 계약의 이벤트/가설/노출/정책 필드를 실험별로 작성할 수 있어야 한다.
3. 가중치 업데이트를 독립 함수로 만들고, **동일 계열 반복 / 다봉우리 보존 / 포화 추정과 반복 노출의 구분**을 단위 테스트로 검증한다.
4. 상태의 가져오기·내보내기를 지원한 뒤에야 여러 채팅 사이 '연속 실험'이라고 부른다.
5. 설계의 새 발견은 관찰로부터 따로 분류하여 L3에 개정한다. 확인하지 못한 사용자 취향을 위키에 확정 사실로 기입하지 않는다.

이 문서의 모든 동역학은 연구용 가설과 운영 정책이다. 독립적인 심리측정 타당도나 통계적 검증이 완료된 것은 아니다.

## 다른 매체: 음악의 장기 개정

이미지의 '한 장 생성·반응'과 나란히 음악에서는 [5초·10초 작곡·청취·개정 프로토콜](../music/README.md)을 사용한다. 취향 가설은 공통으로 다루되 시계열의 구간과 전체 구성, 실제 오디오·작곡 소스의 버전 계보는 독립적인 상태로 보존한다. 공개 위키에 개인별 L2 기록을 자동 게시하지 않는 원칙은 동일하다.
